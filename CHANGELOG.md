# Changelog

## Unreleased

### Changed

- Fixed the Codecks credential adapter's fixed child invocation to use documented `op run --no-masking -- <current Node child>`. 1Password's default stdout masking otherwise rewrites the credential inside its private bounded protocol response, causing a valid externally supplied Codecks credential to be treated as invalid. The flag is limited to that trusted `pi-codecks` protocol; the credential remains forbidden from argv, stderr, diagnostics, logs, and public/model-facing output. Unit and packed fake-manager coverage now faithfully masks stdout without the exact flag and asserts the canonical invocation and inert credential response.
- Added `scripts/start-pi-codecks-external-helper.ps1`, a repository-only trusted local launcher for a fresh normal Pi Codecks session. It uses masked prompts, resolves this source adapter plus trusted local `op` and `pi` applications, validates the sibling development `pi-codecks` package (or an optional explicit trusted package directory), and starts `pi --extension <absolute-package-path>` so no global/project package install is required. Only the non-secret package path is passed in argv; credentials remain in the sanitized process-only child environment. The launcher does not acknowledge live validation, restores the invoking environment, returns Pi's exit code, and remains excluded from package archives. Deterministic fake-application coverage verifies exact package-loading arguments, invalid-package failure, child environment, quote normalization, redaction, exit propagation, and Windows/POSIX restoration without a network or credentials.
- Confirmed the external-provider wrapper preserves the existing `authentication_rejected` category unchanged, including the sibling identity launcher's explicit-empty-identity classification; no wrapper protocol or allowlist change is required.
- Added `-PromptForCodecksAccount` and `-PromptForReference` to the repository-only PowerShell external-provider wrapper. Along with `-PromptForServiceAccountToken`, each switch bypasses inherited process/user/machine configuration for only its selected input and uses a masked prompt, enabling a one-line forced-prompt command without pasting multiline PowerShell.
- Hardened the repository-only PowerShell external-provider wrapper to emit exactly one redacted `operation`/`status`/`category`/`durationMs` object. It preserves only fixed sibling failure categories, rejects malformed or expanded child output, clamps timing to `0..60000`, and defaults to `invalid_configuration` with zero duration without exposing child diagnostics.
- Added `extensions/integrations/codecks-credential-helper.mjs`, a stable non-registered external Codecks credential-helper v1 adapter. It accepts one bounded non-secret request, reads only trusted `PI_ONEPASSWORD_OP_EXECUTABLE`, `PI_ONEPASSWORD_CODECKS_REFERENCE`, and `OP_SERVICE_ACCOUNT_TOKEN` configuration, and uses a fixed current-Node `op run` child. Its overall deadline starts before stdin reading; failure destroys stdin, terminates any active child tree, releases local handles, and uses an unref'd grace deadline to force a silent nonzero result if termination stalls. It strips conflicting 1Password and ambient Codecks credential variables, returns one credential only to the trusted protocol parent, and fails closed without diagnostics for malformed input, lifecycle failures, timeout, cancellation, stderr, or invalid output. Deterministic fake-manager coverage and packed smoke exercise the adapter without a network, account, or sibling package dependency.
- Replaced the superseded packed fixed-identity Codecks orchestrator and repository-only TypeScript launcher with a PowerShell migration wrapper for the normal `pi-codecks` external-provider validation path. The wrapper derives the fixed sibling repository and stable `extensions/integrations/codecks-credential-helper.mjs` adapter, sets/snapshots/restores process-only external-provider configuration, strips conflicting 1Password and ambient Codecks credential variables case-insensitively, reuses process/user/machine account/reference/service-token configuration with masked fallback, suppresses diagnostics, and emits one fixed redacted authentication status. Live execution remains separately authorized.
- Added deterministic supported-surface, real Bash-extension harness, packed-consumer, manifest, and bounded sensitive-content validation. The packed smoke installs a generated tarball offline in a neutral credential-free project and imports the installed Bash extension, Codecks adapter, and trusted helpers without sibling-package imports. Repository and npm-installed packed-package scans fail every high-signal match unless an exact inert file/value pair is allowlisted; bounded regex scanning remains evidence, not proof of secret absence. Tests enforce code/tool contracts because the package intentionally registers no model-facing secret-consuming operation, skill, prompt, or configuration subsystem; provider-backed agent behavior is therefore not available here.
- Removed the deleted ambient-identity `onepassword-read.ts` and `AGENT_OP_ALLOWED_VAULTS` authorization model; least-privilege service-account grants now define the maximum accessible 1Password scope.
- Simplified the Bash lexical guard to block command text mentioning `op` or `op://...`, rather than claiming to prove an invocation; removed obsolete `op-read-allowlist.sh` special handling and documented/tested both false-positive and runtime-construction-bypass limits.
- Rewrote public guidance to distinguish references from plaintext, trusted integration helpers from model-facing tools, server-enforced service-account grants from package checks, and trusted user-level configuration from OS isolation. The guidance now states that the reference and service-account token go only to the trusted 1Password invocation, which resolves the reference before the fixed child receives plaintext solely in its designated environment variable. Added credential-free, non-destructive integration-author migration guidance without claiming a drop-in configuration loader, raw-reader replacement, or model-facing migration endpoint.
- Replaced the ambient 1Password read helper with trusted, fixed-child `op run` contracts that require an explicit service-account token from a trusted launcher (not argv, history, or persisted project configuration) and absolute executables.
- Added bounded cancellation, timeout, output-limit, and non-secret error handling for trusted `op run` invocations.
- Made Bash credential sanitization case-insensitive across all platforms.
- Kept the deterministic loopback fake authenticated identity operation as repository-only Phase 3 test evidence; it is no longer packaged or a public runtime contract.
- Added a repository-only packed composition smoke that generates and installs only the `pi-codecks` and `pi-onepassword` tarballs into a neutral project, verifies both installed package roots are real non-symlink paths inside that project, and exercises installed `pi-codecks` production external-provider exact-read behavior through the installed `pi-onepassword` adapter with inert fake `op` and injected fetch. This repository's development `tsx` loader is only an external harness, not a consumer dependency. It proves successful authentication and selected-helper fail-closed behavior without sibling runtime imports, links, network, or credentials; normal package smoke remains independent.
